# Deployment Notes — Development View

## Source → artefact

```
style.css ─┐
layout.html├─ build_standalone.py ─> dashboard.html ─ update_ph_task.py ─> ph_task 395–398
data.js ───┤        (inline all)                      (per-user header)
dashboard.js┘
   ^
   └── export_data_daily.py  (production PostgreSQL, read-only)
```

`dashboard.html` is a **build output**. Rebuilding from the four parts reproduces the current
file byte-for-byte (checked 2026-09-14: SHA-256
`5d5fc4134feea1e9d7e56be73c982ce0f2087d4043b155b23097b6bdf814b95f`). Never edit it by hand.

## Per-user content

`update_ph_task.py` inserts one line before the Reporting Period header:

```html
<span>Assigned User : <b id="hdr-user">NAME</b></span>
```

The base build contains the target `<span>Reporting Period: <b id="hdr-month">—</b></span>`
exactly once. The script aborts if it finds 0 or more than 1.

## Safety properties of `update_ph_task.py`

- Updates by `task_id`; a missing row is reported and skipped (never inserted).
- Touches only `html_content` and `updated_at`.
- Re-reads every row and compares SHA-256 and length with the per-user source.
- One transaction: **commit only if all four rows verify**, otherwise roll back.

## Environment

- Python 3 with `psycopg` (v3); Node.js for the validation harnesses.
- `DATABASE_URL` must be set in the environment. It is never written to disk by these scripts.
- On Windows consoles set `PYTHONIOENCODING=utf-8` before `validate_range.py`.

## Files deliberately not in Git

`data.js`, `dashboard.html`, `dist/` and the `ph_task` CSV export contain production
business data, and the repository is public. They are listed in `.gitignore` and are
regenerated by the scripts above.
